## Summary

This test plan covers the Append Routes geoprocessing tool enhancement to load routes by route name or routeID with a new Load Field dropdown. It includes verification of default behaviors, route appending scenarios, UI and REST parameter checks, and both positive and negative test cases for route loading and conflict handling.

## Test Cases

### TC-U01 — Verification <!-- src: S5 · label Verification -->

**Steps:**
1. Verify only with Add load type.
2. Verify in append routes GP tool a new drop down named Load Field shows up for loading routes by route name/routeID.
3. When the tool opens, the Load type Add is default and new drop down should show up. Changing load type to Retire by RouteID, Replace by RouteID the drop down should be hidden.
4. The default value for the Load Field drop down is routeID.
5. Verify that the routes are successfully appended using route name by the Add load type.
6. Verify if the routeID field is null, routeID is automatically generated.
7. Verify the corresponding centerlines are created.
8. Verify route name in addition to route ID is shown in the output log file for any incorrect input data.
9. Verify for UN data, existing centerlines are considered, and no new centerlines are created. A new record in Centerline sequence table is created mapping route with the preexisting centerline.
10. In the rest side, verify a new parameter shows up for Load Field. Verify the parameter is optional and works as expected based on the specified value. (routeId routeName)

## Other content

### Test cases

1. Append to default version.

1. Append to a version.

1. Append from a FGDB, EGDB, Feature service - LRS network or any other source network feature class.

1. Selected features in the input data.

1. Append routes with only route name and null routeIDs – RouteIds should be generated.

1. Append routes with same route name with different time slices – All the time slices should have the same routeID generated.

1. Append routes with same route name along with the same routeID with different time slices.

1. Run in python Inline / standalone.

1. Run in model builder with chaining – Append routes- generate CP- generate routes.

1. Test in Pro without starting an editing session.

1. Test one case each for Retire by RouteID and Replace by RouteID load type to ensure everything works as expected.

1. In the UI choose a network with both route name & RouteID, the default load type is Add, drop down for load field is shown. Change the load type to retire by routeID, drop box disappears and again change to the load type Add.  The drop down for the load field should show up.

1. For Conflict prevention, for add type lock is not acquired. (Check the current behavior and continue the same.)
